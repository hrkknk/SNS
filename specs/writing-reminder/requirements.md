# 執筆リマインダー（GPT版）requirements

## 目的

火・木・土の夜、書き出しの材料が Notion に用意されている状態を作る。
材料を作るのは **gpt-5.6-terra**（reasoning medium）。親 Agent は文章に関与しない。

現状は claude.ai の cloud routine（`trig_01HZrSE1UXJHVsdUDfncxNiq`、Opus 5）が担当しているが、
クラウド環境からローカルの codex CLI を呼べないため、ローカル実行に移す。

## 要件

### R1 スケジュール
- 火・木・土 21:00（JST）に自動実行される。
- マシンが停止していて実行時刻を逃した場合は、次回起動時に実行される。
- 実行にあたり、本人の操作を必要としない。

### R2 対象記事の選択
- Notion コンテンツDB（data source `fe59df72-de82-4c4a-add7-be01a0fc64cc`）から1件選ぶ。
- 優先順: ステータス「執筆中」で公開予定日が最も近いもの → 無ければ「ネタ」で公開予定日が最も近いもの。
- 公開予定日が未設定のものしか無い場合は、最後に編集されたものを選ぶ。
- 該当が1件も無い場合は、Notion に何も書かずログだけ残して正常終了する。

### R3 材料の生成
- 対象ページの本文（既存の執筆メモを含む）を取得し、gpt-5.6-terra に渡す。
- 生成させるのは次の4項目:
  - この記事で答えるべき問い（最大3つ）
  - 構成の骨組み（見出しレベルの案を3〜5個、各1行の補足）
  - 関連するネタ（同DBの他ページから最大2つ、関連理由を1行）
  - 詰まりそうな点（1〜2点）
- 記事本文・リード文・段落は生成させない。

### R4 Notion への反映
- 対象ページの本文末尾に、見出し「執筆メモ（YYYY-MM-DD）」を付けて追記する。
- 同じ日付の見出しが既にある場合は、その配下を差し替える。

### R5 本人の原稿を侵さない（最重要）
- 本人が書いた既存のブロックを書き換えない・削除しない。追記のみ。
- ステータスを含むプロパティを一切変更しない。
- 校正や言い回しの提案は行わない（それは別途 `~/SNS/kousei_prompt.md` の役割）。

### R6 ログ
- 実行日時・選ばれた記事・成否を `~/SNS/logs/writing-reminder.log` に追記する。
- 失敗時は原因が分かる情報を残す。

### R7 失敗時の安全側

- Notion API か codex のいずれかが失敗した場合、Notion には何も書かずに終了する。
- 部分的に書き込んだ状態で止まらないこと。

## 非対象

- 記事の代筆、校正、言い回しの提案。
- SNS投稿DBやBufferへの連携。
- 既存のクラウドルーチンの削除（無効化に留める。削除は claude.ai の画面からしかできない）。
